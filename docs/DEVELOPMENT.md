# Development Process

This document describes how Server Toolkit is developed.

---

## Development Workflow

Every feature follows this workflow.

1. Create GitHub Issue
2. Create Feature Branch
3. Implement Feature
4. Commit using Conventional Commits
5. Push Branch
6. Create Pull Request
7. Code Review
8. Merge into main

---

## Branch Naming

feature/<feature-name>

Examples

feature/navigation

feature/home-screen

feature/add-server

fix/login

docs/readme

---

## Commit Convention

feat:

New feature

fix:

Bug fix

docs:

Documentation

refactor:

Internal code improvement

style:

Formatting

test:

Tests

chore:

Maintenance

---

## Coding Rules

- Small classes
- Single Responsibility Principle
- Meaningful names
- English only
- Self-documenting code
- Comments only when necessary
